## Deploy topology

- `render.yaml` (repo root) is a **Render Blueprint** defining both Render
  services. Dashboard → New → Blueprint → pick the repo re-creates them.
- Service names are unique (`-yash20m`) so the `onrender.com` URLs are stable.
- The admin site bakes `VITE_API_URL` in at **build time** — changing the API URL
  means editing that env var and redeploying (Manual Deploy) the admin site.
- The APK bakes `EXPO_PUBLIC_API_URL` in at build time (see `eas.json` preview
  profile and `application/build-apk.ps1`) — same rule: rebuild to change it.

## Environment variables (names only — values live in each provider's dashboard)

### `medpet-api-yash20m` (Render web service)
`NODE_VERSION`, `NODE_ENV`, `DATABASE_URL`, `JWT_SECRET` (auto-generated by Render),
`JWT_EXPIRES_IN`, `ADMIN_NAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `CLIENT_URL`,
`PUBLIC_APP_URL`, `MAIL_HOST`, `MAIL_PORT`, `MAIL_SECURE`, `MAIL_USERNAME`,
`MAIL_PASSWORD`, `MAIL_FROM_EMAIL`, `MAIL_FROM_NAME`, `OSRM_URL`, `NOMINATIM_URL`,
`GEO_USER_AGENT`, `SIMULATION_MODE`.

- `CLIENT_URL` = the admin site origin → drives CORS (Express + Socket.IO).
- `PUBLIC_APP_URL` = this API's own origin → used to build reset/invite links.
- `MAIL_*` = Gmail SMTP + a Google **App Password** (not the account password).
  Leave `MAIL_PASSWORD` blank to disable email (API logs instead of sending).

### `medpet-admin-yash20m` (Render static site)
`VITE_API_URL` (= `<API origin>/api`), `VITE_MAPPLS_STATIC_KEY` (blank — the admin
Live Map tab is disabled until a Mappls web key is added and the site rebuilt).

## Redeploy / update

- **Code change:** push to `master` → Render auto-deploys both services.
- **DB:** persistent on Neon; the API migrates itself on each boot. Nothing to run.
- **Admin URL/API change:** update `VITE_API_URL` (and `CLIENT_URL` on the API) →
  Manual Deploy the admin site.
- **New APK:** `cd application; .\build-apk.ps1 -ApiUrl https://medpet-api-yash20m.onrender.com/api`
  (or the EAS cloud build — `eas build -p android --profile preview` after `eas login`).

## Free-tier limits to remember

- **Render web service** sleeps after **15 min** idle; first request then takes
  ~50 s to wake. 512 MB RAM, 0.1 CPU, 750 instance-hours/month. A single
  UptimeRobot ping to `/health` every 10 min keeps it warm (uses ~730 of 750 hrs).
- **Render static site** is always-on (CDN) and free.
- **Neon** free: 0.5 GB storage, 100 CU-hours/month, auto-suspends after 5 min
  idle (resumes on next connection in ~1 s). No expiry.
- **Uploaded images are NOT persistent** on Render free — the disk is wiped on
  every deploy/restart, so product images uploaded via the admin panel disappear.
  Use image URLs, or move uploads to Cloudinary/S3.
- **APK** is signed with the debug keystore — fine for sideloading/QA, not for the
  Play Store (use `eas build --profile production` for a signed AAB).

## Security notes

- No secrets are committed; `.env` files are git-ignored. Secrets live only in the
  Render/Neon dashboards.
- The Neon DB password was exposed once during setup — rotate it in the Neon
  console (Roles → reset password) and update `DATABASE_URL` in Render if desired.
